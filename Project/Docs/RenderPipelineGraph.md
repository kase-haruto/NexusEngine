# 描画パイプラインのノード編集

ウィンドウ → **描画パイプライン**（英語: Render Pipeline）を開きます。imnodesを使用したドッキング可能なノードパネルです。

パネルのタブやタイトルバーをエディタの外へドラッグすると、独立したOSウィンドウとして使用できます。ほかのImGuiパネルも同じ操作に対応します。エディタ内へドラッグして戻すこともできます。外部パネルの閉じるボタンは、そのパネルだけを閉じます。

初期構成は次の接続です。

```text
Scene (HDR) → Bloom → Tone Mapping / Grading → FXAA → Output
```

「パスを追加」からVignette、カスタムHLSL、FXAA、Bloom、Tone Mappingを追加できます。出力ピンから入力ピンへドラッグして接続します。既存の入力へ接続すると、それまでの入力を交換します。中ボタンドラッグでキャンバス移動、Ctrl+クリック／ピンのドラッグで切断、Deleteまたは「選択を削除」でノード・リンクを削除します。SceneとOutputは削除できません。Undo／Redoボタンは接続やパラメーターの変更を戻します。

マウスホイールでカーソル位置を中心に25～200%へ拡大・縮小します。文字・ピン・リンク・背景グリッドも同時に拡縮します。「全体を表示」でノード群へ表示を合わせ、「100%」で標準倍率へ戻します。拡縮とキャンバス移動は表示だけの変更で、保存するノード座標や描画処理の設定は変わりません。

キャンバスを右クリックすると、クリック位置へのパス追加、選択の削除、右クリックしたノードの接続切断、Undo／Redo、全体表示、100%への復帰を行えます。ノードやリンクの上で右クリックした場合は、その対象を選択します。数値を編集中やコンボボックスの表示中は、ホイールでキャンバスを拡縮しません。

「自動適用」が有効なら、接続と設定の変更を次フレームの描画前に適用します。無効なら「適用」を押します。ノードの移動だけではGPU設定を作り直しません。HLSLファイルを編集した場合は「HLSLを再読込」を押します。エラーはパネルに表示し、直前の有効な描画構成を維持します。

## パスと接続の意味

| ノード | 入力 → 出力 | 設定 |
|---|---|---|
| Scene | なし → HDR | シーン描画結果。Gridもこの画像に含む |
| Bloom | HDR → HDR | 有効・無効、強度、しきい値、ソフトニー |
| Tone Mapping / Grading | HDR → Color | 露出、変換方式、彩度、コントラスト、ガンマ |
| Vignette | Color → Color | 強度、有効・無効 |
| Custom HLSL | Color → Color | Project Root相対のHLSLパス、entry、float4×4の定数 |
| FXAA | Color → Color | 有効・無効。表示色のパス間で移動可能 |
| Output | Color → なし | UI描画前の最終画像 |

HDRピンとColorピンは直接接続できません。Tone Mappingを経由します。循環・同じ入力への複数接続を拒否します。OutputからSceneまでたどった経路だけを実行するため、未接続の試作ノードは画面へ影響しません。

このグラフは**単一の色画像を渡すポストプロセス用**です。Bloomは有効経路に最大1件、Tone Mappingは必須で1件です。Bloomの複数解像度処理や露出・色調整は既存のHDR Backendへコンパイルし、表示色のパスは接続順に中間画像を交互に使って実行します。深度・法線・Compute・任意の描画資源を結ぶRenderGraphではありません。独自HLSLの契約は[シェーダー拡張](ShaderExtensions.md)と共通です。

ゲームの `Level::ScreenEffects()` はグラフの表示色パスの後へ追加します。ゲーム固有のエフェクトよりFXAAを後にしたい場合は、ゲームの効果列にもFXAAを登録するか、共通のグラフへ効果を配置してください。

## 保存と単体起動

「保存」でプロジェクトのConfigディレクトリに `RenderPipeline.json` を原子的に保存します。ノード、接続、パラメーター、位置を含みます。「読込」で復元し、Editorの次回起動と単体ゲーム起動でも読み込みます。未接続のドラフトも保存可能ですが、単体起動ではSceneからOutputへの完成した経路が必要です。保存前に適用結果を確認してください。パネルを閉じるだけでは未保存の変更をディスクへ保存しません。

Live Codingではドラフトの値をスナップショットへ保存し、新しいコード側で復元します。ImNodesやImGuiのポインターを持ち越しません。

コードからは `PostProcessGraph::Compile()` でCPU検証・実行計画生成、`GraphicsSystem::SetPostProcessGraph()` で適用できます。`LoadPostProcessGraph()` / `SerializePostProcessGraph()` はEditor非依存です。

## Grid

XZ平面のGridは全画面三角形から床面との交点を計算します。X軸が赤、Z軸が緑です。画素あたりのワールド距離に応じて `…0.01 / 0.1 / 1 / 10 / 100…` の目盛りを滑らかに切り替えます。遠ざかると粗く、近づくと細かくなり、有限平面の端は表示しません。深度による遮蔽、線の平滑化、水平線付近のフェードを行います。`GridSettings::spacing` は基準単位で、固定のマス幅ではありません。

## 検証

- EditorTests: ピンの型、循環拒否、実行順、FXAA配置、JSON保存復元、適用のキュー、英日UIとimnodesコンテキスト寿命。
- EditorTests: ノードの寸法が90フレーム・親ウィンドウのサイズ変更を通して増加しないことを確認。
- EditorTests: ホイール入力によるカーソル位置の維持、倍率上限・下限、拡縮後の移動・ドラッグ、座標の保存、右クリックメニューの追加・削除・切断・Undo、全体表示を検証。
- NexusImGuiTests: 実GPU・WARPで独立したHWNDとSwapChain、シーン画像の表示、文字入力、リサイズ、メインウィンドウへの復帰、閉じる操作、外部パネルを残した終了を検証。メイン描画のGPU投入後に外部パネルを描き、フレームのFenceに含めます。
- GraphicsTests `--adaptive-grid`: 赤いX軸・緑のZ軸、10倍ずつのズームでの表示密度、遠景・水平線。確認画像は `Generated/GridPreview/*.bmp`。
- GraphicsTests `--viewport-preview`: グラフの適用、不完全グラフの拒否、主ビュー／カメラプレビューの独立した資源管理を実GPU・WARPで検証。
